# ForteVision · Datathon 2026

Видеопроверка кассовых операций: локальная Qwen3-VL-4B-Instruct, нормативная база НБРК и веб-интерфейс с доказательными кадрами.

## Что делает сервис

- Принимает MOV до 100 МБ / 180 секунд, без обработки звука и идентификации лиц.
- Извлекает визуальные признаки пяти областей кадра, классифицирует динамику обученной моделью и уточняет события в перекрывающихся временных окнах.
- Сопоставляет видимые события с семью правилами из постановления НБРК № 231 от 29.11.2019.
- Возвращает бинарный вердикт, время, объяснение и 1–3 оригинальных JPEG. Если видеоклассификатор обнаружил нарушение, а VLM не подтвердила его тип, возвращает явную отметку для ручной проверки и `normative_reference: null`, без выдуманной нормы.
- Работает без внешних AI API. После загрузки весов модель использует только локальные файлы.

Это прототип для поддержки проверки специалистом. Отсутствие найденного события не доказывает соблюдение всех процедур. Неполные фрагменты, действия вне кадра, мелкие предметы и новый ракурс могут снижать качество. Шкала confidence не является калиброванной вероятностью.

## Архитектура

`MOV → кадры с PTS → frozen Qwen visual tokens → 5 regions / motion classifier → Qwen / local rules → original JPEG → FastAPI / UI`

Финальный вариант: лёгкий классификатор движения поверх замороженного визуального энкодера. Для четырёх четвертей кадра и центральной области считаются временное стандартное отклонение, средняя и 90-я перцентиль межкадровой разности. StandardScaler + LogisticRegression, C=0.001, порог 0.35. Оба финальных классификатора обучены на 40 уникальных видео из `open.zip`. Временной классификатор предлагает кадр только при неподтверждённом типе. Нормативные тексты хранятся отдельно от весов. Обученные LoRA-адаптеры проверены, но не выбраны из-за ложных тревог.

`forte/rules.json` содержит краткие формулировки, ссылки, условия и исключения. Применение нормы выбирается из фиксированного набора: модель не генерирует номера законов. Веса не используются как хранилище нормативных текстов. Например, отсутствие физического удостоверения не доказывает отсутствие цифровой идентификации, а один сотрудник в клиентской операции не считается нарушением пункта 42.

## Запуск на GPU

Проверенное окружение: NVIDIA L4, PyTorch 2.8.0 + CUDA 12.8, Python 3.12, Transformers 4.57.1. Около 9 ГБ весов, от 12 ГБ VRAM и 16 ГБ RAM. Для конкретной нагрузки проверяйте запас памяти.

```bash
export FORTE_HOME=/home/ubuntu/forte-datathon
mkdir -p "$FORTE_HOME"
git clone https://github.com/song-ev/Datathon-2026.git "$FORTE_HOME/src"
python3.12 -m venv "$FORTE_HOME/.venv"
"$FORTE_HOME/.venv/bin/pip" install torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cu128
"$FORTE_HOME/.venv/bin/pip" install -r "$FORTE_HOME/src/requirements.txt"
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/download_model.py"
bash "$FORTE_HOME/src/scripts/run.sh"
```

Для воспроизводимого скачивания задайте `MODEL_REVISION` сохранённым SHA из `model-manifest.json`. Во время обработки установлены `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, отключена телеметрия Hugging Face. У процесса нет клиентов внешних модельных API.

Для воспроизведения обученной версии нужны подготовленные `data/audit.json` и видео в `data/videos/`. Затем:

```bash
export PYTHONPATH="$FORTE_HOME/src"
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/train_detector.py"
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/train_video_detector.py"
```

Эти команды используют только 24 development-группы. Артефакты `models/video-detector.joblib` и `models/event-detector.joblib` уже установлены на сервере. Без них сервис использует исходный VLM baseline; это другая модель с другим качеством. Для явного baseline: `DETECTOR_MODE=rules`.

Это команды воспроизведения **старой** версии. Финальный вариант на всём открытом наборе:

```bash
export PYTHONPATH="$FORTE_HOME/src"
export DETECTOR_MODE=trained
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/cache_features.py"
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/train_open_cv.py"
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/train_spatial.py"
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/train_fusion.py"
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/train_spatial_localizer.py"
DETECTOR_MODE=fusion bash "$FORTE_HOME/src/scripts/run.sh"
```

Режим `fusion` поддерживает смесь общего контекста и движения. Выбранный вес
общего контекста равен 0: фактически используется только пространственное движение.
Нужны `models/fusion-detector.joblib` и `models/spatial-localizer.joblib`.
В systemd режим задаётся через `Environment=DETECTOR_MODE=fusion` в drop-in.
Возврат к прежней модели: `DETECTOR_MODE=trained` и перезапуск сервиса.

Для запуска после перезагрузки VM: `bash "$FORTE_HOME/src/scripts/install_service.sh"` (требует sudo, пути рассчитаны на сервер Ubuntu). Проверка: `sudo systemctl status fortevision`. Журнал: `sudo journalctl -u fortevision`.

Первый запуск создаёт случайный API-ключ в `$FORTE_HOME/private/api-key.txt` с правами `0600`. Ключ передаётся жюри отдельно от Git. В интерфейсе кнопка «API-ключ» сохраняет его в sessionStorage текущей вкладки.

Сервис слушает порт 8000. Публикуйте его через HTTPS reverse proxy; доступ к API защищён ключом. Если Brev требует NVIDIA login, автоматическая проверка жюри не сможет пройти: для **этого порта приложения** нужен публичный HTTPS-адрес. Не публикуйте Jupyter или SSH без отдельной защиты.

Dockerfile предоставлен для переноса (сборку контейнера следует отдельно проверить):

```bash
docker build -t fortevision .
docker run --gpus all --rm -p 8000:8000 -v /path/to/forte-data:/data fortevision
```

Каталог `/data` должен быть доступен UID 1000 для записи, а веса — находиться в `/data/models/Qwen3-VL-4B-Instruct`.

## API жюри

```bash
curl -X POST https://YOUR_HOST/api/v1/analyze \
  -H "X-API-Key: YOUR_KEY" -F "file=@example.mov"
# {"job_id":"..."}
curl https://YOUR_HOST/api/v1/jobs/JOB_ID -H "X-API-Key: YOUR_KEY"
```

Ответ POST: 202. Статусы задания: `processing`, `done`, `failed`. Готовый ответ содержит `verdict: violation | no_violation`, `violations`, поля `type`, `timecode_sec`, `description`, `evidence_frames[].timestamp_sec`, `evidence_frames[].image_base64`. Дополнительно: `normative_reference`, `confidence`, `analysis`.

Ошибки: 401 — ключ, 415 — расширение, 422 — некорректное видео, 413 — размер, 503 — модель ещё загружается. Занятый GPU больше не вызывает 429: валидные видео принимаются с 202 в FIFO-очередь после завершения загрузки и проверки. Один dispatcher последовательно передаёт задания одному GPU worker. Ожидающее задание сохраняет статус `processing`, этап «Ожидание в очереди» и `queue_position` (1 — следующее; 0 — уже не в очереди). Health возвращает `queue_length`.

Общий дедлайн — 295 секунд от поступления HTTP-запроса в приложение, включая загрузку, проверку и очередь; 5 секунд оставлены на опрос результата. Worker получает только оставшееся время. Просроченное задание получает `failed / TimeoutError`, активный зависший worker перезапускается. Отдельный watchdog завершает просроченные ожидающие задания даже во время обработки или перезапуска GPU. Ошибка одного видео не блокирует следующие. Незавершённые задания после перезапуска всего сервиса получают `failed / Restarted` и требуют повторной отправки.

Дедлайн ограничивает ожидание, но `failed` не считается успешной обработкой по ТЗ. Для произвольно большой очереди один GPU не гарантирует готовый результат за 5 минут. Проверка реальной нагрузки: `python scripts/check_queue.py` отправляет подряд синтетический неподдерживаемый ролик и пять самых длинных уникальных видео открытого набора, проверяет отсутствие 429, продолжение после ошибки и время от начала POST до получения `done`. Содержимое видео и ответы модели остаются на сервере; наружу выводятся только статусы и времена.

Проверено на L4 через публичный HTTPS API 17.10.2026: все 6 загрузок вернули 202,
5/5 реальных видео завершились `done`; неподдерживаемая синтетика — ожидаемый
`failed / UnsupportedScene`. Максимальная длина очереди — 5, ожидание реального
видео — до 63,001 с. Полное время пяти запросов: 18,127 / 27,195 / 55,078 /
63,696 / 86,512 с (ролики длительностью 142,533 / 78,733 / 72,7 / 71,6 / 65,3 с).
Некорректный MOV при занятом GPU вернул 422, следующие задания не пострадали.
19 unit-тестов и 12 API smoke-проверок прошли. Это подтверждение времени для
проверенной серии, а не гарантия для неизвестной нагрузки и любых видео.

`GET /api/v1/health` — готовность без секретов. `GET /api/v1/rules` — база норм, требует ключ. Документация схемы: `/docs`.

Видео и JSON заданий удаляются после 24 часов хранения, проверка очистки каждые 5 минут. Датасет разработки в `data/` этим правилом не затрагивается.

## Оценка качества

Весь `open.zip` является открытым обучающим набором. Ограничение ТЗ на обучение
касается скрытых тестовых видео, которые жюри отправляет через API. Внутреннее
разделение 24/16 ниже использовалось только для разработки и не является тестом
организаторов. Финальную модель можно обучать на всех 40 уникальных открытых видео.
Каталог API-загрузок `runtime/` скрипты обучения не читают.

Дополнительные эксперименты: `scripts/train_lora.py` (BF16 LoRA, глобальные или
12-секундные окна), `scripts/train_temporal.py` (временная CNN с признаками «до/после»),
`scripts/train_open_cv.py` (четыре разбиения и обучение на всех 40 видео),
`scripts/train_spatial.py` (пять областей сетки визуальных признаков, динамика и
нелинейные классификаторы). Все вычисления и промежуточные результаты остаются
на собственном сервере. LoRA меняет 5 898 240 параметров языковых attention-слоёв
4B-модели; визуальный энкодер остаётся замороженным.

Для пространственного эксперимента после подготовки данных:

```bash
export PYTHONPATH="$FORTE_HOME/src"
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/train_spatial.py"
```

В перекрёстной проверке SHA-дубликаты объединены, каждый ролик оценивается моделью,
не обученной на нём. Выбор модели и порога по этим предсказаниям делает итоговые
цифры **оценкой разработки**, а не независимым результатом теста жюри. Сравнивайте
модели на одинаковых разбиениях; исторические 56,25% на 16 роликах напрямую с
четырёхблочной оценкой на 40 роликах не сопоставимы. После выбора финальное обучение
на всех 40 роликах не создаёт новой независимой оценки качества.

Исходный набор: 42 файла, 40 уникальных SHA-256, 21 уникальный положительный / 19 отрицательных. Два дубликата группируются. Для одного положительного дубликата размечены разные времена — сохраняются обе отметки.

Разделение детерминированное и стратифицированное по SHA: 24 development / 16 holdout (8+8). Сценарные дубликаты, не совпадающие побайтно, не размечены, поэтому это ограничение оценки. Разметка содержит только бинарный класс и время: точность классификации типов по ней измерить нельзя.

```bash
export PYTHONPATH="$FORTE_HOME/src"
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/evaluate.py" --split dev
# Выбор EVENT_THRESHOLD только на development, затем один зафиксированный запуск:
EVENT_THRESHOLD=0.65 "$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/evaluate.py" --split holdout
"$FORTE_HOME/.venv/bin/python" -m unittest discover -s "$FORTE_HOME/src/tests" -v
"$FORTE_HOME/.venv/bin/python" "$FORTE_HOME/src/scripts/api_smoke.py"
```

Полные предсказания и описания остаются в `private/`. В терминал выводятся только агрегаты. Тесты жюри не используются для обучения или подбора порогов. Измерения приведены ниже; синтетический smoke-тест не является оценкой качества на реальных видео.

### Обновлённая оценка разработки, 17 октября 2026

Четыре одинаковых стратифицированных разбиения всех 40 SHA-групп; каждый раз
30 обучающих / 10 проверочных видео. Сравнение ниже относится к классификаторам,
а не к качеству нормативных объяснений. Подбор конфигураций и порога выполнялся
на этих же out-of-fold предсказаниях, поэтому оценки оптимистичны.

| Метрика | Прежний общий классификатор | Пространственное движение |
|---|---:|---:|
| Accuracy | 57,5% | 62,5% |
| Recall нарушений | 52,4% | 71,4% |
| Precision | 61,1% | 62,5% |
| Пропуски / 21 нарушение | 10 | 6 |
| Ложные тревоги / 19 нормальных | 7 | 9 |
| TP / FP / TN / FN | 11 / 7 / 12 / 10 | 15 / 9 / 10 / 6 |

Локализатор: 8 из 21 положительных роликов в пределах ±2 секунд в четырёх
разбиениях, независимо от бинарного вердикта. Это слабая локализация, требующая
доработки. Финальные веса переобучены на всех 40 роликах; скрытые тесты жюри
недоступны, их качество неизвестно. Повторное измерение на этих 40 после финального
обучения не было бы независимым тестом.

LoRA на 18 видео при чувствительном пороге дала на прежних 16 проверочных
роликах TP=6, FP=8, TN=0, FN=2 (37,5% accuracy); она не развёрнута. Временная CNN
также не выбрана после перекрёстной проверки. Вес Qwen3-VL-8B скачан как резерв,
но обучение 8B и аренда второго GPU не запускались.

Проверка развёрнутой версии: 14 unit-тестов и 12 API-проверок прошли. Реальный
запрос вернул 3 оригинальных JPEG с правильными размерами и временными отметками,
12,131 с на L4. Сохранённые признаки и обработка того же видео заново дают одинаковую
оценку классификатора. Исправлены Windows-переносы строк в стартовых shell-скриптах;
`.gitattributes` закрепляет LF, регрессионный тест проверяет это условие.

### Историческая версия: 24 development / 16 holdout

| Проверка | Результат |
|---|---|
| VLM baseline, development 24 | accuracy 37.5%, F1 0.286 |
| Обученный видеоклассификатор, development leave-one-video-out | accuracy 66.7%, F1 0.667; подбор параметров на этой же выборке |
| Зафиксированный полный pipeline, holdout 16 | accuracy **56.25%**, precision **60%**, recall **37.5%**, F1 **0.4615** |
| Матрица holdout | TP=3, FP=2, TN=6, FN=5 |
| Локализация ±2 секунды | 2 из 8 положительных видео (25%) |
| Успешно обработано | 16/16; максимум 11.884 с на L4 |

После оценки добавлена проверка допустимой сцены: геометрические фигуры и другие неподходящие записи отклоняются со статусом `failed`, кодом `UnsupportedScene`. Она не обучалась на holdout. Приведённое время измерено до добавления этой проверки.

Это слабое качество, недостаточное для самостоятельного контроля. Независимая оценка показывает ограничение переноса даже внутри небольшого датасета. Высокая скорость и рабочий API не означают высокую точность. Порог не изменялся после просмотра holdout. Не измерены качество типов, корректность нормативного объяснения и работа на новом ракурсе. Следующий шаг — ручная разметка типов и начала событий, разделение по сценариям/камерам, сбор сложных отрицательных примеров.

## Бюджет и эксплуатация

Остановите инстанс через Brev после проверки жюри; хранение диска может продолжать тарифицироваться. Остановка Python-процесса не останавливает оплату VM.

Датасет, модель, журналы с содержимым видео и ключи исключены из Git. Модель Qwen3-VL-4B-Instruct опубликована под Apache-2.0; её лицензия сохраняется вместе с загруженными весами.

На текущем сервере настроено выключение гостевой ОС на **18.10.2026 19:00 по Астане, UTC+5** (18.10 14:00 UTC). Прогноз общей стоимости до этого времени — около $25 при плановом тарифе $0.88/час. Это дополнительная защита, не лимит биллинга Brev: после дедлайна проверьте состояние **Stopped** в консоли и при необходимости нажмите Stop. Минимальная плата за диск может сохраняться. Отмена таймера: `sudo systemctl disable --now fortevision-budget-stop.timer`.

После добавления проверки сцены она пропустила 40/40 уникальных реальных видео (24 development + 16 holdout); синтетический ролик отклонён. Это проверка совместимости, не новая независимая оценка детекции. 5 unit-тестов и 12 API-проверок пройдены. Внешние HTTP-проверки: readiness 200, API без ключа 401, база норм с ключом 200.
